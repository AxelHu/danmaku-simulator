本轮在同一部 91 分钟长片上测试可选的 `video_intro`。40 次请求均成功，得到 40 个结构有效候选；选入 23 条后，原 2,803 条轨道变为 **2,826 条**。原有每条弹幕的文字、时间和其他字段全部保持不变。

**这次小样没有显示整体质量优势。** 对 40 对结果打乱 A/B 标签后，由本对话的两个内置代理各审读 20 对：更偏好简介组 14 对、历史原组 17 对、接近 9 对。这属于探索性的历史对照，不能由此宣布简介有效或无效，也不能把它当作模型排名或真人观看评测。

完整匿名数值见 [聚合数据](data/video-intro-2026-11-06.json)。本报告不发布私人片名、片源、实际简介全文、原始对白、生成文本、设备地址或账号资料。原始请求、响应、比较材料和部署回执保留在私有运行目录。

## 1. 改了什么

此前独立生成请求只包含当前检查点、近期对白/画面和观众设定。本轮给每个视频的配置增加可选 `video_intro`，独立生成和接话都可使用。简介在共享上下文中排在变化的检查点与事件之前，个人设定仍放在后面。

本次简介为 **100 个字符**，只保留题材、系列身份、主角的初始背景，并注明初始背景不等于本片当前实力或处境。它来自本对话对片前基础资料的筛选，没有使用完整 STT 的剧情总结，也没有自动从官方宣传梗概复制全文。

非空简介启用对应的系统约束：背景不是当前画面事实，不证明当前人物身份、关系或行为，不允许凭背景补全后续剧情。生成仍要绑定当前目标事件，互动仍要引用当前证据。简介不获得事件 ID。

缺省、`null`、空字符串或纯空白走原请求路径；相同旧输入继续命中旧缓存。非空简介去掉首尾空白后参与请求身份，改变有效文字会隔离新缓存。未改供应商客户端、CLI 或调度器。具体用法见 [VIDEO_INTRO.md](VIDEO_INTRO.md)。

## 2. 如何比较

从全片约等长的 20 个时间区间各选择一个有明确观察目的的检查点，每点一位 MiniMax 观众、一位 DeepSeek 观众，共 40 对。选点覆盖名称与指代、对白立场、场景意义、危险与能力边界，也包含基础简介不应强行改变反应的画面点。这是有目的抽样，并非随机代表整个视频库。

| 条件 | 处理 |
| --- | --- |
| 历史基线 | 复用实际成功请求的原始回执；40 个对应候选都仍在原 2,803 条池中 |
| 新组请求 | 40 次真实调用；MiniMax 20、DeepSeek 20 |
| 对齐的输入 | 同模型设置、同观众、同检查点、同局部事件、同目标事件、同采样 variant |
| 改变的输入 | 基础简介，以及仅在简介非空时启用的背景系统约束 |
| 分析复用 | 直接读取已经完成的分析，新增 STT 为 0，新增视觉调用为 0 |
| 新组结果 | 40 / 40 请求成功，无失败重试，无沉默，保留 40 个候选 |
| 常规过滤 | 有一次返回超过每请求一条的上限，额外一条未进入候选，费用仍完整记录 |
| 响应留档 | 40 份逐次原始响应均已核对字节数与 SHA-256，无覆盖或截取 |

全量请求计划只在内存中重建，用于定位准确任务；仅选中的 40 个新请求被实际执行。计划客户端的空返回不作为模型输出，也没有保存为生成结果。历史基线是从文件读取，不计为本轮新 API 调用或客户端缓存命中。

新增组中可以看到更具体的语境反应、针对当前称呼的疑问或由对白产生的轻吐槽；也存在换一个程度副词、从具体反差退回泛化感叹、或增加较弱功能类比的情况。背景提供了明确的语境入口，但局部证据、观众风格和随机采样仍显著影响实际文本。

这里没有独立人类评审，没有重复采样以估计方差，也没有同期重新生成不含简介的控制组。两种模型分配的观众角色不同；输入同时增加了简介与对应约束。结果不能分离每一项变化的因果效应，更不能外推成所有视频的提升比例。

两位代理没有把新增组中的任何一条判为必须强制拒绝。普通观众的担心、猜问或轻吐槽不因带有推测就自动算错；较弱的推断可以在比较和本次选入时不采用。最后的取舍由协调代理结合原池附近内容完成，属于工程审读和编辑选择。
