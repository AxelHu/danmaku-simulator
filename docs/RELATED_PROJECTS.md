## 对本项目的含义

以下是设计判断，不是关于上游项目的额外事实：

- **存在直接同类项目。** 本项目不以“首个 AI 视频弹幕生成器”作为定位；Asteria 是最重要的现有参照。
- **核心实验是独立观众与时间因果关系。** 每位观众可选择模型和风格；公共视频证据可以共享，具体反应独立生成，再由调度器控制出现时间、热度和复读。生成时只能使用该时刻已经披露的内容。
- **语音、视觉、时间与来源应能追溯。** 保存带时间的转写、逐帧观察和弹幕所依据的事件，便于检查误识别、时间漂移与提前剧透。
- **费用账本是产品能力的一部分。** 本次阅读的资料未展示覆盖全部阶段的输入、输出、缓存、失败重试与金额统计；本项目应实际记录这些数据，不凭模型名字推算“便宜”。
- **优先复用成熟的展示和格式能力。** 播放器与 ASS 转换可独立评估；观众生成、证据约束、调度和成本统计保持可替换接口。研究模型与数据集用于后续评估，不阻塞首版闭环。

## 缓存与复读需要分开统计

这也是本项目的设计判断：

| 机制 | 目的 | 应如何计数 |
| --- | --- | --- |
| 转写与画面分析缓存 | 同一素材重跑时复用前处理 | 记录本地命中，避免再次请求 |
| 服务端提示词缓存 | 多位观众共享视频证据的前缀 | 以提供方返回的缓存 token 为准；未报告时不声称发生命中，总用量或价格缺失则保留未知 |
| 同一上下文的独立采样 | 得到新的观众反应 | 每次实际调用分别记账，不声称结果缓存命中 |
| 已有生成结果的受控复用 | 模拟短时跟风与复读 | 记录结果复用，不冒充新的模型调用或新观众原创 |

本地推理没有按次 API 账单，并不意味着硬件、运行时间与能源没有成本。对没有单价或真实用量的调用，应保留“未知”或“参考估算”，不能填零制造已完成计费的印象。

## 搜索范围的边界

搜索结果中还会出现现有弹幕下载器、播放器、针对弹幕的统计分析，以及弹幕射击游戏的弹型生成。它们不应被混为“根据视频生成文字评论”。

例如 [hl3805/Bilibili-AI-Danmaku-Model](https://github.com/hl3805/Bilibili-AI-Danmaku-Model) 的仓库内容主要分析 AI 话题视频的已有弹幕，不能仅凭名称归为同类生成器。[ClassComet 论文](https://arxiv.org/abs/2504.18189) 研究教育视频中的 AI 弹幕，但本次未确认可用的对应 GitHub 实现，因此未作为可直接复用的仓库列入上表。
