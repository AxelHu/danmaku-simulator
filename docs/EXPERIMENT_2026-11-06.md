# 首次真实视频实验：Sintel 预告片

测量日期：2026-11-06。结论是：**从实际视频到可播放弹幕的链路已经跑通，事件触发让反应更及时，API 参考成本较低；内容仍需要继续打磨。** 本文记录一次迭代实验，不是模型排行榜，也不是大样本观看体验评测。

## 素材与复现

使用 Blender Foundation / Durian Open Movie Project 的 **Sintel trailer**，52.208333 秒，854 × 480。视频许可为 [CC BY 3.0](https://creativecommons.org/licenses/by/3.0/)，来源见 [官方下载页](https://durian.blender.org/download/) 与 [预告片页面](https://durian.blender.org/news/sintel-teaser/)。本项目增加了中文 AI 弹幕；原视频没有包含在仓库中。

下载文件 SHA-256：`b670602fa00934ca27c4351bb0efe7ea7a07fae57284e44226025eeed7c51254`。

无需模型密钥即可回放已经生成的结果：

```bash
python3 tools/prepare_sintel_demo.py
python3 -m danmaku_sim serve --port 8793
# 打开 http://127.0.0.1:8793/?run=sintel-recorded
```

脚本会下载约 4.2 MiB 的公开视频并校验哈希。已有同一视频也可用 `--video /path/to/trailer.mp4`。页面中的用量是 **2026-11-06 的历史测量**，回放本身不调用模型。

完整公开证据在 [examples/sintel](../examples/sintel/)：包含视觉观察、转写、候选、最终弹幕、配置、去掉请求标识与缓存键的逐请求用量、汇总与缓存验证。`baseline/` 保留第一版结果。原始供应商响应及密钥不发布。

对自己的视频重新生成，使用 README 的 `run` 命令和新的输出目录。公开样例的账本是历史记录，不应当作新运行的空账本。模型响应缓存没有发布，因此重新生成样例会发生新的模型请求；它不会复制本次测量值。

## 做了两轮什么实验

两轮都使用四类观众：随手看、细节党、轻吐槽、共情党。前两类由 MiniMax M3.1 Flash 生成，后两类由 DeepSeek Flash 生成。人设与模型绑定，因此不能从这些样本推断哪一个模型更擅长弹幕。

| 项目 | 第一版 baseline | 改进版 v2 |
| --- | --- | --- |
| STT | MiniMax asr-1.0 实际转写一次 | 导入第一版的真实转写 |
| 关键帧 | 12 张，MiniMax 视觉观察 | 同样 12 张，DeepSeek 视觉观察 |
| 触发方式 | 6 秒固定窗口 | 9 个有效事件检查点，近邻事件合并 |
| 观众采样轮数 | 1 | 2 |
| 每次最多生成 | 2 条 | 1 条，最长 20 字符 |
| 模型生成调用 | 25 | 63 |
| 目标反应随机区间 | 0.35–3.8 秒 | 0.35–1.8 秒 |
| 最终独立弹幕 | 31 | 63 |
| 人工复读 | 3 | 2 |
| 最终总弹幕 | 34 | 65 |

转写得到一句英文对白，时间为 12.18–14.36 秒。视觉帧时刻为 0.3、6、12、16.65、18、24、26.025、27.567、30、36、42、48 秒。v2 的 4 个低信息事件仍可进入历史，但不单独触发观众请求。

v2 同时改变了视觉模型、观察提示词、生成提示词、检查点、采样轮数与调度参数。这些变化共同构成迭代结果，不能把改善全部归因于某一项。

### 时间和文字长度

| 指标 | baseline | v2 |
| --- | ---: | ---: |
| 平均反应延迟 | 3.154 秒 | 1.711 秒 |
| 反应延迟中位数 | 2.998 秒 | 1.635 秒 |
| P90 反应延迟 | 4.854 秒 | 2.772 秒 |
| 最大反应延迟 | 7.089 秒 | 3.288 秒 |
| 平均文字长度 | 13.65 字符 | 10.46 字符 |
| 10 字符以内 | 8 / 31（25.8%） | 36 / 63（57.1%） |

上述指标只统计独立弹幕，不包含人工复读。反应延迟定义为 `comment.time - event_available_at`，是**播放时间轴上的排程延迟**，不是模型 API 的计算耗时。P90 使用最近秩 `ceil(0.9 × n)`；若使用下取分位数算法，v2 为 2.635 秒，公开 metrics 同时保留两种口径。文字长度含标点。

本原型是预先生成、播放时呈现。v2 的视觉分析实际约 34.2 秒，观众生成约 138.2 秒，并发设为 2；这些阶段不包含本轮已复用的 STT。

### 为什么减少了复读

v2 收紧复读限制前的中间排程有 7 条人工复读，其中有些是长句，有些因为密度限制排到了很后面；这与 baseline 的 3 条是不同阶段的结果。最终只对不超过 8 字符的短句复读，并要求在父弹幕出现后 2 秒内、原有最大反应期限内放得下；放不下就丢弃。因此最终为 2 条复读。

这次调整只重新编排同一批候选，没有新采样。独立弹幕的时间没有改变。不同观众独立生成相同文字仍可保留，不把“相同文字”直接当作错误。

## Token、缓存和成本

费用单位均为 **USD**，按请求保存的价格快照估算。MiniMax 使用订阅渠道，DeepSeek 使用按量渠道；订阅用量的按量等价费用只是资源参考，不能当作实扣账单。`actual_cost` 保持 `null`。DeepSeek 使用核验日期的峰时单价，没有假设实际账单已按非峰时优惠结算。

| 指标 | baseline | v2 本轮新增工作 |
| --- | ---: | ---: |
| 实际 API 请求 | 38（含 1 次 STT） | 75（未重复 STT） |
| 输入 token，含缓存读 | 40,573 | 64,883 |
| 其中缓存输入 token | 8,290 | 26,747 |
| 输出 token | 2,570 | 3,234 |
| 提供方输入缓存比例 | 20.43% | 41.22% |
| 按量部分估算 | $0.00376838 | $0.00725572 |
| 订阅部分按量参考 | $0.01007712 | $0.00422371 |
| 本轮合计参考成本 | **$0.01384550** | **$0.01147943** |
| 加上一份完整 STT 后的参考成本 | **$0.01384550** | **$0.01699031** |

v2 不是在更少完整成本下生成了更多弹幕：其本轮复用了 STT。比较从原视频独立开始的成本，应看最后一行。第二轮之所以调用多于第一轮，是增加了采样次数，同时事件触发数量也不同。

### 分阶段明细

| 阶段 | baseline 请求 / 参考费用 | v2 请求 / 参考费用 |
| --- | ---: | ---: |
| STT | 1 / $0.00551088 | 0 / $0；复用原转写 |
| 视觉观察 | 12 / $0.00186503 | 12 / $0.00221160 |
| 弹幕生成 | 25 / $0.00646960 | 63 / $0.00926783 |

v2 生成阶段单独的输入缓存命中为 **45.18%**。按相同前缀安排请求确实产生了缓存读取，但这一次实验不能说明两轮采样一定带来同样比例，也不能区分模型切换、提示词变化和请求时序各自的贡献。

### 完整结果复用验证

对 v2 使用完全相同的分析、模型提示词、观众与采样设置重新执行 CLI `generate`；调度器应用新的复读限制。验证时对网络请求入口设了监测并禁止发起网络请求。

| 证据 | 结果 |
| --- | ---: |
| CLI 退出码 | 0 |
| 新增本地缓存复用记录 | 63 |
| 监测到的网络尝试 | 0 |
| 累计实际请求数 | 75 → 75 |
| 累计参考成本 | $0.01147943 → $0.01147943 |
| 本次执行耗时 | 0.081 秒 |

这证明已有结果可用于恢复与重新排程。它不等于 63 个新观众样本，也不等于供应商提示词缓存：新的独立采样仍需要输出 token。

### 经济性判断

在这个 52 秒样本上，包含一份 STT 的完整参考成本约 **1.70 美分**，API 费用没有成为首要瓶颈。若机械按时长同比例放大，约为 **$1.17 / 视频小时**，但这只是量级估算，**尚未实测一小时视频**。对白密度、事件密度、帧数上限、上下文长度、观众数量、生成轮数和缓存都会改变成本与质量，不能把这个数当作报价。

更直接的节省方式是导入已有字幕、复用素材分析、减少低信息事件请求、控制观众与轮次。不要为了缓存命中率而人为填充无用 token。当前 120 帧上限也会影响长视频覆盖率，需要按视频类型评估。

价格与口径来源：[MiniMax 价格](https://platform.minimax.io/docs/pricing/overview)、[MiniMax 提示词缓存](https://platform.minimax.io/docs/api-reference/text-prompt-caching)、[DeepSeek 价格](https://api-docs.deepseek.com/quick_start/pricing/)、[DeepSeek 上下文缓存](https://api-docs.deepseek.com/guides/kv_cache/)。核验日期：2026-11-06。

## 质量观察与下一轮重点

有些弹幕已经较接近即时反应，例如“她被吓到了？”、“这眼神，看到啥了”、“伸手想摸它吗”。但也出现了画面复述、生硬的笑话和不自然的中英混用；“B 站味”目前是提示词目标，没有通过独立用户评测。

单帧识别存在不确定性。雪地痕迹、雾中轮廓、幻想生物等观察可能出错；不同观众独立生成，也可能一起继承同一条上游错误。共享证据能省成本，并不能使错误相互抵消。时间约束能禁止提前利用后续事件，却不能保证每句语义正确或没有模型既有作品知识带来的剧透。

下一轮应选对白密集、游戏实况、知识讲解三类素材，保持配置可比，评估相关性、可笑性、重复的自然程度和安静段是否合理。必要时为动作场景增加短帧序列或声效事件，再判断这些额外输入是否改善观看体验，避免只追求更高弹幕密度。
